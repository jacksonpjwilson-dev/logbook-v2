## Food/Nutrition implementation and verification boundary

Implemented persistent Food flows include meal creation/rename/expand/edit; the exact four Add Food choices (Search Foods, Scan Barcode, Manual Entry, Recent Foods); local and remote search; favorites as an independent filter; quantity confirmation and serving conversion with only verified food-specific portions; manual personal foods; barcode lookup and unknown-barcode manual fallback; recipes with ingredient/yield nutrition; Add/Replace meal/day copying with recoverable replacement; date-specific calorie/macro targets; remaining values and adherence; seven-day trends; hydration quick-add/custom amounts, goals and history; Food History correction and Recently Deleted recovery, with 30-day retention, early permanent deletion and automatic expiry for food logs, water logs and recipes; offline persistence; and food navigation from Home.

Canadian Nutrient File and Open Food Facts use public HTTP endpoints with attribution/source metadata and no app credential. The unit suite tests the provider response parser and data rules, but does not establish live endpoint uptime, licensing review, provider completeness, camera scanning on hardware, or offline behavior under every failure mode. Barcode camera access uses AVFoundation; CI only exercises its manual fallback because simulator camera scanning is not a meaningful physical barcode test. Run #84 executed Food tests but failed due to the selected-date persistence bug and a stale sheet-dismissal assumption. The selected-date write bug is fixed locally by persisting the explicit `date` argument. Local candidate `edb4f74` adds date swiping, hydration/target/favorite/recents/recipe UI coverage and 30-day recycle-bin handling for food logs, water logs and recipes; latest changes including the selected-date fix are not yet published or tested. UI coverage still needs to be expanded for recipe editing/logging, meal copy Add/Replace, goal/history controls, hydration, favorites/recent flows, day swiping/calendar selection and live/offline provider failure.
